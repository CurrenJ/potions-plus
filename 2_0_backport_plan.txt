THE SHAPE OF THE DELTA
Three workstreams, one of them irrelevant
Those 128 commits are not one stream of work. They split cleanly into three, and knowing which is which is what keeps this from being a year of wasted effort.

Workstream	Span	What it is	Verdict
A · Feature era	Jun–Sep 2025
~60 commits	1.21.5-era gameplay: genetic crops, farming skill, growing mossy blocks, the Grungler, clothesline and skill-journal work.	Triage
B · Migration era	Apr–May 2026
~40 commits	1.21.5→26.1.2 plus the common/neoforge multiloader split. Chunks 2–7, Identifier renames, split-package fixes, platform abstraction.	Out of scope
C · Devolution & alchemy	Aug 2026
~28 commits	The 2.0 cut list, the alchemy/ layer, PUtil's retirement, and the behaviour fixes that came with them.	Backport
The load-bearing insight
Workstream A is largely cancelled by workstream C. Genetic crops, the farming skill, the fish tank and the entire Skills system were added during A and deleted during C. Porting them forward into 1.21.1 would be building things you then delete in Phase 1 of this same plan.

Only four things from A survive to the 26.1.2 tip: growing mossy blocks, the Grungler, the clothesline refinements, and the ore-flower placement widening.

THE PLAN
Six phases, ordered so each one shrinks the next
Devolution comes first for the same reason it did on the 26.1.2 branch: every file you delete in Phase 1 is a file you never migrate, test or re-datagen in Phases 2–5. Tick items as you land them — progress saves for everyone with the link.

CARRIED FORWARD
Gotchas the 26.1.2 branch already paid for
Lifted from DEVOLUTION_PROGRESS.md — these cost real time on the first pass. They apply verbatim to 1.21.1.

Re-run datagen after every removal, even source-only ones. src/generated/resources drifts silently; one pass swept 947 stale files because datagen had not run since two commits earlier.
Build before datagen. If runData throws Missing item model definitions for something you just deleted, the jar is stale — rebuild first, don't assume the removal was wrong.
runData never exits on its own. Run it backgrounded, watch for the Caching: total files: summary or a settled working tree, then kill it. A hang is not a failure.
Verify by diffing file counts, not exit codes. Spot-check that moss, salt, wormroot, brewing cauldron and awkward potion still have generated models before trusting a big deletion count.
Save compatibility. Worldgen removal is the only cut that breaks existing worlds. fcefc14 also notes that the PpIngredient hashing change re-rolls seeded potion recipes in pre-existing worlds, accepted with no migration path.
